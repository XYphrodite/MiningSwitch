# Mining Switch 4 - Контекст проекта

## Обзор проекта

Mining Switch — настольный дашборд для ПК с майнингом: одной большой кнопкой запускаются и останавливаются XMRig (CPU) и lolMiner (GPU) через локальный `mining-fleet-agent`, значок возле часов держит приложение в одном клике, а примерная оценка дохода покрывает и этот ПК, и все воркеры общих кошельков сети. Приложение никогда не меняет кошельки, учётные данные и настройки выплат.

**Платформа**: Windows 10/11, .NET 10 (`net10.0-windows`), WPF
**Язык**: C# 14
**Область**: Майнинг-операции / настольный дашборд

---

## Технический стек

### Среды выполнения и фреймворки

- **.NET 10** (`net10.0-windows`) — интерфейс WPF, `NotifyIcon` из WinForms для трея
- **.NET 10 Desktop Runtime** — требуется на целевом ПК (есть везде, где работает `mining-fleet-agent`)
- Релиз — один framework-dependent `MiningSwitch.exe` (~0,2 МБ)

### Ключевые зависимости

| Пакет / компонент | Версия | Назначение |
|-------------------|--------|------------|
| Microsoft.WindowsDesktop.App | 10.x | WPF + WinForms (значок в трее) |
| `mining-fleet-agent` | Устанавливается отдельно | Локальный API управления майнерами (`/api/v1`, loopback) |
| Публичный API HashVault | v3 | Статистика CPU-воркера, данные сети, курс XMR/RUB |
| Публичный API LuckyPool | taric29 | Статистика GPU-воркера (Tari C29), курс из калькулятора пула |
| Публичный API CoinGecko | v3 | Курс XTM/RUB |

NuGet-пакетов в самом приложении нет; DTO и клиент агента адаптированы из
[mining-fleet](https://github.com/XYphrodite/mining-fleet) (`MiningFleet.Contracts`,
`AgentClient`). Для тестов используется xUnit.

## Архитектура

`MiningSwitch.exe` — единое WPF-приложение. Оно находит локального агента через
`%ProgramFiles%\mining-fleet-agent\appsettings.json` и опрашивает его по loopback с
заголовком общего секрета. Доходность считается по публичным API пулов по таймеру —
ничего не накапливается и не сохраняется на диск.

```
┌─────────────────────────────────────────────────────┐
│  MiningSwitch.exe (WPF, один экземпляр, значок)     │
│  ┌──────────────┐  ┌──────────────┐  ┌───────────┐  │
│  │ Дашборд      │  │ Управление   │  │ Таймеры   │  │
│  │ майнеры,     │  │ большая      │  │ опрос 4 с │  │
│  │ доход,       │  │ кнопка,      │  │ ресурсы   │  │
│  │ ресурсы      │  │ меню трея    │  │ доход 5м  │  │
│  └──────┬───────┘  └──────┬───────┘  └─────┬─────┘  │
└─────────┼─────────────────┼────────────────┼────────┘
          │                 │ loopback HTTP  │
          │        ┌────────▼────────┐       │
          │        │ mining-fleet-   │       │
          │        │ agent /api/v1   │       │
          │        └────────┬────────┘       │
          │                 │                │
    ┌─────▼─────┐    ┌──────▼──────┐   ┌─────▼──────┐
    │  XMRig    │    │  lolMiner   │   │ Публичные  │
    │  (CPU)    │    │  (GPU)      │   │ API:       │
    └───────────┘    └─────────────┘   │ HashVault, │
                                       │ LuckyPool, │
                                       │ CoinGecko  │
                                       └────────────┘
```

Ключевые принципы дизайна:

- **Один экземпляр**: именованный мьютекс `Local\MiningSwitch.UI`; повторный запуск подаёт
  сигнал `Local\MiningSwitch.Show`, чтобы показать существующее окно.
- **Контракт агента**: подмножество DTO и `AgentClient` взяты из mining-fleet, поэтому
  приложение следует за этим API; 404 на `gpu` просто означает старого агента.
- **Честные неполные данные**: когда один источник дохода недоступен, общая сумма не
  показывается — видна доступная часть с пояснением, а не уверенно неверное число.
- **Выключение с сохранением**: ручное выключение выставляет политику агента
  (`minerWanted`, `gpuWanted`, `autoStartMiner` …), которая переживает перезагрузки.

## Компоненты проекта

### 1. **App (`App.xaml`, `App.xaml.cs`)**
**Тип**: Точка входа WPF-приложения
**Расположение**: `src/MiningSwitch.App/`

**Ключевые возможности**:
- Аргументы: `-Tray` (запуск в трей), `--selftest <path>` (проверка без окна: агент, пулы, ресурсы → JSON-отчёт)
- Мьютекс одного экземпляра + событие показа существующего окна
- Self-test выполняется вне потока диспетчера (блокирующее HTTP на UI-потоке приводит к deadlock)

### 2. **MainWindow (дашборд и управление)**
**Тип**: Окно WPF
**Расположение**: `src/MiningSwitch.App/MainWindow.xaml(.cs)`

**Ключевые возможности**:
- Карточки статуса XMRig и lolMiner с живой скоростью, большая кнопка питания обоих майнеров
- Карточка дохода: этот ПК (CPU + GPU, ₽/сутки) и прогноз по всей сети, обновление каждые 5 минут
- Плитки ресурсов (CPU / RAM / свободное место C:, D:) каждые 12 секунд
- Логика управления повторяет семантику mining-fleet: `PUT /config` политики, затем
  `miner/start|stop`, `gpu/start|stop`, затем подтверждающий опрос; частичные результаты — с предупреждением
- Крестик прячет окно в трей; меню значка: открыть / включить / выключить / закрыть

### 3. **Сервисы**
**Тип**: Код внутри проекта приложения
**Расположение**: `src/MiningSwitch.App/Services/`

**Ключевые возможности**:
- `AgentClient` + `Contracts` — подмножество API агента из mining-fleet (loopback, `X-Fleet-Token`)
- `IncomeService` — оценка CPU (HashVault: средний хешрейт за 24 ч × 86400 × награда / сложность
  − комиссия пула, × XMR/RUB) и оценка GPU (конверсия `profit24hPer1Ghs` из LuckyPool − комиссия,
  × XTM/RUB из CoinGecko); котировки старше двух часов отклоняются
- `ResourceMonitor` — загрузка CPU (`GetSystemTimes`), RAM (`GlobalMemoryStatusEx`), диски (`DriveInfo`)

### 4. **Тесты**
**Тип**: xUnit
**Расположение**: `tests/MiningSwitch.Tests/`

**Ключевые возможности**: перенос проверок расчётов из старого `Test-Features.ps1` —
работа с комиссией, преобразования единиц, свежесть котировок.

## Сборка и запуск

```powershell
# Сборка
dotnet build src/MiningSwitch.App -c Release

# Тесты
dotnet test tests/MiningSwitch.Tests -c Release

# Релиз (один exe, на целевом ПК нужен .NET 10 Desktop Runtime)
dotnet publish src/MiningSwitch.App -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o publish

# Проверка без окна (пишет JSON-отчёт)
.\publish\MiningSwitch.exe --selftest report.json
```

### Установка (на любом ПК)

```powershell
powershell -c "irm https://raw.githubusercontent.com/XYphrodite/MiningSwitch/main/install.ps1 | iex"
```

### Известные проблемы ⚠️
- Суммы дохода — прогноз, а не начисления: PPLNS, удача пула и электричество не учитываются (по замыслу)
- Общая сумма по сети не показывается, пока недоступен источник GPU (по замыслу)
- Приложению нужен .NET 10 Desktop Runtime; без него `install.ps1` останавливается с понятной ошибкой (Дата: 2026-10-07)
