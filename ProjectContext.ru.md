# Mining Switch 3 - Контекст проекта

## Обзор проекта

Mining Switch 3 — настольное приложение Windows для одного ПК (`MOSCOW_ENJOYER`), которое управляет XMRig (CPU) и lolMiner (GPU) одной большой кнопкой и значком возле часов, оценивает доход своего воркера и всей сети и выполняет уход за Windows (очистка временных файлов, игровой режим, схемы питания). Приложение общается с локально установленным `mining-fleet-agent` через loopback и читает публичные API пулов (HashVault, LuckyPool) для оценки дохода — оно никогда не меняет кошельки, учётные данные и настройки выплат.

**Платформа**: Windows, PowerShell 5.1 + WPF (`.NET Framework`), лаунчер на C#
**Язык**: PowerShell, C#
**Область**: Мониторинг майнинга / настольная утилита

## Технический стек

### Среды выполнения

- **Windows PowerShell 5.1** (`#requires -Version 5.1`, запуск только с `-STA`)
- **.NET Framework** — WPF (`PresentationFramework`, `PresentationCore`, `WindowsBase`) для интерфейса, `System.Windows.Forms` / `System.Drawing` для значка в трее и диалогов
- **C#** — `Launcher.cs`, компилируется в `MiningSwitch.exe` на целевом ПК через `csc`

### Ключевые зависимости

| Пакет / компонент | Версия | Назначение |
|-------------------|--------|------------|
| Windows PowerShell | 5.1 | Среда выполнения всего интерфейса и логики |
| PresentationFramework (WPF) | .NET Framework | Главное окно, вкладки, элементы управления |
| System.Windows.Forms | .NET Framework | NotifyIcon (трей), MessageBox |
| System.Net.Http | .NET Framework | Loopback-запросы к API `mining-fleet-agent` |
| Встроенный Windows `curl` | Встроен в Windows | Публичные запросы к API пулов (без окна, без токена агента) |
| `mining-fleet-agent` | Устанавливается отдельно (`%ProgramFiles%\mining-fleet-agent\appsettings.json`) | Локальный API управления майнерами |

Внешние сервисы: **HashVault** (пул Monero + котировка XMR/RUB), **LuckyPool** (GPU-пул Tari C29), **CoinGecko** (котировка XTM/RUB). Документация API пула: <https://hashvault.pro/monero/api>

## Архитектура

`MiningSwitch.exe` — тонкий лаунчер на C#: он запускает скрытый `powershell.exe -STA -File MiningSwitch.ps1`, который владеет окном WPF и значком в трее. Интерфейс опрашивает локальный агент по loopback о состоянии и управлении майнерами; более тяжёлая работа (запросы к публичным API, журналы дохода, анализ очистки, схемы питания) выполняется фоновыми заданиями из `MiningSwitch.Features.ps1` и возвращается в интерфейс через очередь результатов.

```
┌────────────────────────────────────────────────────┐
│  MiningSwitch.exe (лаунчер C#, без окна консоли)   │
└───────────────────────┬────────────────────────────┘
                        │ powershell.exe -STA -File
┌───────────────────────▼────────────────────────────┐
│  MiningSwitch.ps1 — интерфейс WPF + значок в трее  │
│  (один экземпляр через мьютекс Local\MiningSwitch.UI)│
│  ┌─────────────────┐    ┌───────────────────────┐  │
│  │ Вкладки:        │    │ Таймеры / очереди     │  │
│  │ · Майнинг и     │◄──►│ заданий (агент,       │  │
│  │   доход         │    │  функции)             │  │
│  │ · Уход за ПК    │    └───────────┬───────────┘  │
│  └─────────────────┘                │              │
└───────┬─────────────────────┬───────┴──────────────┘
        │ HTTP loopback       │ dot-source
┌───────▼────────┐   ┌────────▼──────────────────────┐
│ mining-fleet-  │   │ MiningSwitch.Features.ps1     │
│ agent API      │   │ (доход, очистка, питание,     │
│ (локальный)    │   │  ресурсы, публичный JSON)     │
└────────────────┘   └───────┬───────────┬───────────┘
                             │           │
                     ┌───────▼───┐   ┌───▼──────────┐
                     │ HashVault │   │ LuckyPool +  │
                     │ (XMR, ₽)  │   │ CoinGecko    │
                     └───────────┘   └──────────────┘

Файлы состояния: %LOCALAPPDATA%\MiningSwitch\earnings.json (+ резервная копия),
                 gpu-share-earnings.json
```

Ключевые принципы дизайна:

- **Один экземпляр**: именованный мьютекс `Local\MiningSwitch.UI`; повторный запуск подаёт сигнал `Local\MiningSwitch.Show`, чтобы показать уже работающее окно, а не открывать второе.
- **Асинхронные задания**: фоновая работа ставится в очередь (`Queue-Feature`) и выполняется по одному заданию; результаты возвращаются через `Handle-FeatureResult`, поэтому поток интерфейса не блокируется на сети или диске.
- **Очередь управления**: команды агенту (старт/стоп, игровой режим) проходят через `Add-Operation` → `Begin-Request` → `Handle-Response`, что сериализует переходы состояния.
- **Консервативная оценка**: доход всегда помечается как оценка (средний хешрейт за 24 ч × награда блока / сложность, минус комиссия пула), а не как баланс выплат.

## Компоненты проекта

### 1. **Лаунчер (`Launcher.cs` / `MiningSwitch.exe`)**
**Тип**: Консольный лаунчер без окна (скомпилированный EXE)
**Расположение**: `Launcher.cs` → `MiningSwitch.exe`
**Назначение**: Запускает `MiningSwitch.ps1` скрытно, чтобы окно консоли PowerShell не появлялось.

**Ключевые возможности**:
- Проверяет, что `MiningSwitch.ps1` лежит рядом с EXE; при ошибке показывает MessageBox
- Принимает ровно один аргумент: `-Tray` (запуск сразу в трей)
- Запускает `powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -STA -WindowStyle Hidden -File ...` с `CreateNoWindow=true`

### 2. **Основной интерфейс (`MiningSwitch.ps1`)**
**Тип**: Приложение WPF (PowerShell)
**Расположение**: `MiningSwitch.ps1`
**Назначение**: Окно, значок в трее, вкладки, таймеры и всё взаимодействие с пользователем (тексты интерфейса на русском).

**Ключевые возможности**:
- Вкладки: **«Майнинг и доход»** (состояние майнеров, большая кнопка питания, оценка дохода) и **«Уход за ПК»** (очистка, игровой режим, схемы питания)
- Параметры: `-Tray` (запуск в трей), `-SelfTest`, `-PreviewPath` / `-PreviewCare` (превью интерфейса), `-SmokeReportPath` (интеграционная проверка WPF только на чтение: статус майнера, доход, ресурсы, анализ Temp)
- Большая кнопка управляет **обоими** майнерами: XMRig (CPU) и lolMiner (GPU); остановка второго выполняется даже при ошибке первого, при частичном выполнении показывается предупреждение
- Плитки ресурсов (CPU / RAM / свободное место C: и D:) обновляются примерно каждые 12 секунд; доход обновляется каждые 5 минут или по кнопке «Обновить доход»
- Ручное выключение сохраняется после перезагрузки (записывается в состояние); включение запускает майнеры и разрешает автозапуск
- Крестик сворачивает окно в трей; «Выход» в меню значка закрывает интерфейс, сохраняя состояние майнинга

**Зависимости**:
- `MiningSwitch.Features.ps1` (подключается dot-source для фоновой работы)
- `settings.json` (имя компьютера, имя воркера пула)
- `MiningSwitch.ico` (значок окна и трея)

### 3. **Модуль функций (`MiningSwitch.Features.ps1`)**
**Тип**: Модуль PowerShell (dot-source)
**Расположение**: `MiningSwitch.Features.ps1`
**Назначение**: Вся работа вне интерфейса. Никогда не меняет кошельки и учётные данные майнеров.

**Ключевые возможности**:
- **Доход**: `Get-WorkerQuote` / `Get-EarningsSnapshot` (HashVault, CPU, воркер `moscowenjoyer`), `Get-LuckyQuote` / `Get-GpuEarningsSnapshot` (LuckyPool, Tari C29, воркер `MOSCOW_ENJOYER`); `Update-EarningsLedger` ведёт журнал приростов с привязкой к ПК и хешу сочетания кошелька с воркером (первое наблюдение — только исходная точка, сбросы счётчика и повторные наблюдения игнорируются, смена кошелька начинает новую историю)
- **Котировки**: XMR/RUB из рыночных данных HashVault, XTM/RUB из CoinGecko (`minotari`); котировки старше двух часов отклоняются
- **Уход за ПК**: `Find-CleanupCandidates` / `Remove-CleanupCandidates` (файлы старше 7 дней в Temp пользователя, `Windows\Temp`, `D:\Temp`, `D:\TMP`; пропускаются новые, изменённые после анализа, занятые файлы и обход точек монтирования; только разрешённые корни), `Get-ResourceSnapshot`, `Get-ActivePowerScheme` / `Set-PowerScheme` / `Invoke-PowerCfg`
- **Сохранение состояния**: `Write-AtomicJson` / `Read-SavedJson` с восстановлением из `.bak`; состояние в `%LOCALAPPDATA%\MiningSwitch\` (`earnings.json`, `gpu-share-earnings.json`)
- Публичный HTTP через скрытый Windows `curl` (`Get-PublicJson`) с ограничением времени; токен агента используется только в памяти для loopback

### 4. **Тесты (`Test-Features.ps1`)**
**Тип**: Тестовый скрипт на проверках (assert), без фреймворка
**Расположение**: `Test-Features.ps1`
**Назначение**: Проверяет расчёты, сохранение истории и безопасность очистки на любом ПК с Windows.

**Ключевые возможности**:
- Доход: привязка к своему ПК, комиссия пула, исходная точка (без выдуманной истории), приросты, повторные наблюдения, сбросы счётчика, разделение историй по кошелькам, переподключения, отклонение устаревшей котировки, отклонение отсутствующего воркера
- GPU-доход: преобразование единиц (сложность принятых долей против `g/s`), изоляция своего воркера, сумма по сети, устаревший курс XTM, некорректный хешрейт
- Очистка: фильтры по возрасту и дате создания, защита изменённых и занятых файлов, непереход через точки монтирования, отклонение путей вне корня, атомарная запись с восстановлением из резервной копии
- Запуск: `powershell.exe -STA -File Test-Features.ps1`

## Сборка и запуск

### Запуск

```powershell
# Обычный запуск (окно консоли не появляется)
MiningSwitch.exe

# Запуск сразу возле часов
MiningSwitch.exe -Tray
```

На целевом ПК приложение установлено в `C:\Program Files\MiningSwitch`, ярлык — на рабочем столе и в автозагрузке пользователя. Все файлы из архива должны лежать рядом с EXE.

### Тесты и интеграционная проверка

```powershell
# Тесты (математика дохода, журналы, безопасность очистки)
powershell.exe -STA -File Test-Features.ps1

# Интеграционная проверка WPF только на чтение (пишет файл отчёта)
powershell.exe -STA -File MiningSwitch.ps1 -SmokeReportPath report.txt
```

### Сборка

```powershell
# Лаунчер компилируется НА ЦЕЛЕВОМ ПК (локального процесса сборки нет):
csc /target:winexe /out:MiningSwitch.exe Launcher.cs
```

### Известные проблемы ⚠️
- Суммы дохода — это **оценка**, а не выплаты: PPLNS, удача пула и электричество не учитываются (по замыслу)
- История дохода до первого запуска не восстанавливается; сброс счётчика пула или пропуски наблюдений могут занизить накопленный результат (при сбросе показывается предупреждение)
- Несколько CPU-подключений к одному воркеру показывают предупреждение (переподключения не удваивают сумму)
- Сборка выполняется на целевом ПК; повторяемого скрипта сборки в репозитории нет (Дата: 2026-09-28)
